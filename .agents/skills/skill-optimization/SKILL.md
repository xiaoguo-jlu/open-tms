# Skill 优化技能

## 目的

基于实践经验，持续优化 Open-TMS 的所有 Skill，避免重复犯错，提升团队协作效率。

## 触发条件

**每次完成开发迭代后**，当出现以下情况时，必须运行此技能：
- 修复了 bug
- 发现了规范/文档与实际代码不一致
- 测试脚本未能捕获的问题
- 跨 Skill 协作时出现信息不一致

## 优化维度

### 一、流程优化 (Process)

检查以下流程问题：
1. **前置检查缺失**：某个 Skill 在执行前没有做必要的检查
2. **后续验证缺失**：开发完成后没有验证就提交
3. **信息传递断链**：上游 Skill 的输出没有正确传递到下游

### 二、规范优化 (Standards)

检查以下规范问题：
1. **规范与代码不一致**：文档说一套，代码是另一套
2. **规范与规范矛盾**：两个文档互相矛盾
3. **规范过于模糊**：只有概念没有具体值
4. **规范缺失**：某种场景没有规范约束

### 三、工具优化 (Tools)

检查以下工具问题：
1. **测试脚本缺陷**：测试用例没有覆盖边界情况
2. **模板代码错误**：示例代码有 bug
3. **验证机制缺失**：没有自动化检查

## 优化流程

### 步骤1：收集问题（从实践中来）

**输出格式**：
```
## 本次迭代发现的问题

### 问题1：[简短描述]
- 发现场景：
- 根本原因：
- 影响范围：
- 违反的规范：

### 问题2：[简短描述]
...
```

### 步骤2：分类归因

对每个问题，判断属于哪个维度：

| 类别 | 判断标准 | 示例 |
|------|----------|------|
| 流程问题 | 人的行为顺序或检查点缺失 | 没做自测就提交 |
| 规范问题 | 文档/规范写的不对或不全 | code值文档与代码不一致 |
| 工具问题 | 脚本/模板/验证机制有缺陷 | 测试只检查HTTP状态不检查body |

### 步骤3：确定优化方案

| 问题 | 优化方案 | 责任人 | 完成时间 |
|------|----------|--------|----------|
| 问题1 | 修改Skill A第X行 | AI自动 | 当时 |

### 步骤4：执行优化

#### 4.1 流程优化

在相关 Skill 中增加检查点或调整步骤顺序。

#### 4.2 规范优化

修改对应文档，确保：
1. 规范描述具体明确（有具体值、示例）
2. 与代码实现一致
3. 不同文档之间互相呼应

#### 4.3 工具优化

修改测试脚本、模板代码，增加防御性检查。

### 步骤5：验证优化

修改完成后，验证：
1. 修改后的内容逻辑正确
2. 与相关文档保持一致
3. 不会引入新问题

## 本次实践案例分析

### 发现的问题

#### 问题1：MyBatis-Plus 乐观锁导致 updateById 失败

- **发现场景**：Currency/Trader/Country 的 updateById 和 deleteById 报错
- **根本原因**：实体继承 BaseEntity 有 @Version，MyBatis-Plus 乐观锁检查失败
- **影响范围**：所有带 @Version 的实体
- **违反的规范**：db-design skill 未提及此注意事项

#### 问题2：响应 code 值不一致

- **发现场景**：规范文档写 `code: 0`，实际代码返回 `code: 200`
- **根本原因**：文档示例使用 Spring MVC 风格，与 JAX-RS 实际实现不一致
- **影响范围**：所有 API 响应
- **违反的规范**：api-design skill + 开发规范文档

#### 问题3：ServiceImpl getById 递归调用

- **发现场景**：查看 SKILL.md 第395-398行
- **根本原因**：模板代码 `{Entity} entity = getById(id);` 写错，应为 `baseMapper.selectById(id)`
- **影响范围**：按此模板开发的新实体
- **违反的规范**：backend-dev skill 示例代码错误

#### 问题4：ServiceImpl 缺少存在性检查

- **发现场景**：删除/更新不存在的记录时无错误提示
- **根本原因**：deleteById/updateById 没有先查询验证
- **影响范围**：所有实体的删除和更新操作
- **违反的规范**：backend-dev skill 缺少此质量要求

#### 问题5：测试脚本只检查 HTTP 状态

- **发现场景**：API 返回 HTTP 200 但 code=500 时测试仍通过
- **根本原因**：test_crud.py 只检查 `response.status_code == 200`
- **影响范围**：所有 CRUD 测试
- **违反的规范**：缺少对 response.json()["code"] 的检查
