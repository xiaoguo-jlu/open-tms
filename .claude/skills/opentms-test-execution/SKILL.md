# Open-TMS 测试执行 Skill (QA)

## 简介

本skill用于Open-TMS项目的测试执行工作，指导测试工程师完成从测试准备到缺陷跟踪的完整测试执行流程。

---

## 一、触发条件

**当需要进行以下工作时，触发本skill：**

- 测试用例已设计完成，需要执行测试
- 开发提交代码，需要进行回归测试
- 发现缺陷，需要验证修复
- 上线前需要进行验收测试
- 需要编写测试报告

**触发信号：**
- Dev完成功能开发，通知QA进行测试
- PM-Lead分配测试执行任务
- CI/CD自动触发测试
- 缺陷修复后需要重新验证

## 四、执行步骤

### 步骤1：测试准备

**目的**：确认测试环境和待测版本。

**操作**：

1. **确认测试环境**
   - 测试环境地址是否可用
   - 测试账号权限是否正常
   - 数据库是否已初始化

2. **确认待测版本**
   - 获取代码分支
   - 确认构建版本
   - 记录版本信息

3. **准备测试数据**
   - 初始化测试数据
   - 准备边界测试数据
   - 准备异常测试数据

4. **阅读测试用例**
   - 理解每个用例的测试目的
   - 确认前置条件
   - 确认预期结果

**输出**：
- 测试环境确认清单
- 测试版本信息
- 测试数据准备就绪

### 步骤2：功能测试执行

**目的**：按测试用例执行功能测试。

**操作**：

1. **按优先级执行**
   ```
   P0用例 → P1用例 → P2用例
   ```

2. **执行UI功能测试**
   - 进入对应页面
   - 按测试步骤操作
   - 验证实际结果
   - 记录执行状态（通过/失败/阻塞）

3. **记录测试结果**
   - 通过：实际结果符合预期
   - 失败：实际结果与预期不符
   - 阻塞：因前置条件不满足无法执行

4. **保存证据**
   - 失败用例截图
   - 错误日志
   - 操作录屏（如有必要）

**用例执行状态**：
| 状态 | 含义 | 后续动作 |
|------|------|----------|
| Pass | 测试通过 | 继续下一用例 |
| Fail | 测试失败 | 创建缺陷单 |
| Block | 阻塞 | 记录阻塞原因 |

### 步骤3：API接口测试执行

**目的**：使用自动化脚本验证后端接口正确性。

**操作**：

1. **确认测试环境和脚本**
   - 后端服务必须运行在 `http://localhost:8081`
   - 确认测试脚本位置：`scripts/test/` 目录下各模块测试脚本
   - 运行器脚本：`.agents/skills/opentms-test-execution/scripts/run_tests.py`

2. **选择测试套件并执行**
   ```bash
   # 列出所有可用测试套件
   python .agents/skills/opentms-test-execution/scripts/run_tests.py list

   # 运行指定模块测试
   python .agents/skills/opentms-test-execution/scripts/run_tests.py run basedata  # 基于数据模块
   python .agents/skills/opentms-test-execution/scripts/run_tests.py run ac        # 现金流模块
   python .agents/skills/opentms-test-execution/scripts/run_tests.py run at        # 转账模块

   # 运行全部测试套件
   python .agents/skills/opentms-test-execution/scripts/run_tests.py run all

   # 查看历史报告
   python .agents/skills/opentms-test-execution/scripts/run_tests.py report basedata
   ```

3. **测试套件说明**
   | 套件 | 测试范围 | 测试文件 |
   |------|----------|----------|
   | basedata | 币种/国家/银行/交易对手等基础数据API | scripts/test/basedata/test_all_post.py |
   | ac | 实际现金流(AC) API | scripts/test/ac/test_ac_api.py |
   | at | 账户转账(AT) API | scripts/test/at/test_at_api.py |
   | full | 完整测试套件 | scripts/test/test_full.py |

4. **记录接口测试结果**
   - 脚本自动运行并输出测试结果
   - 失败用例自动记录到 `test/reports/` 目录
   - 查看报告：`python run_tests.py report <suite>`

5. **快速验证（可选）**
   仅当需要快速验证单个接口时使用curl：
   ```bash
   # 健康检查
   curl -X GET "http://localhost:8081/api/health"

   # 列表查询
   curl -X GET "http://localhost:8081/api/v1/currencies"
   ```

**注意**：正式测试必须使用 `run_tests.py` 脚本，禁止手写测试命令。手写curl仅用于快速探路验证。

### 步骤4：E2E端到端测试

**目的**：验证完整业务流程。

**操作**：

1. **识别核心业务流程**
   - 交易录入→审批→执行→结算
   - 账户新增→交易→账户余额
   - 资金调拨→调拨确认→调拨完成

2. **按场景执行**
   - 完整成功路径
   - 异常中断路径
   - 并发操作场景

3. **跨模块验证**
   - 数据流转一致性
   - 模块间接口调用
   - 状态同步

### 步骤5：缺陷创建与跟踪

**目的**：记录和管理发现的缺陷。

**操作**：

1. **创建缺陷单**
   ```bash
   gh issue create \
     --title "[Bug] {模块}-{简短描述}" \
     --body "## Bug编号\nBUG_XXX\n\n## 基本信息\n..." \
     --label "QA,Bug"
   ```

2. **缺陷定级**
   | 严重程度 | 定义 | 示例 |
   |----------|------|------|
   | 高 | 核心功能不可用 | 登录失败、支付异常 |
   | 中 | 功能有问题但可绕过 | 显示格式错误、校验不准确 |
   | 低 | 体验问题 | 页面样式偏差、提示文字错误 |

3. **跟踪缺陷状态**
   ```
   待修复 → 修复中 → 待验证 → 已关闭
   ```

4. **验证缺陷修复**
   - 重新执行相关测试用例
   - 确认修复有效
   - 更新缺陷状态

### 步骤6：回归测试

**目的**：确保新代码未破坏已有功能。

**操作**：

1. **确定回归范围**
   - 直接影响：修改代码涉及的模块
   - 间接影响：调用被修改接口的其他模块
   - 核心流程：P0用例覆盖的功能

2. **执行回归测试**
   - 优先执行P0用例
   - 执行与修改相关的P1用例
   - 选择性执行P2用例

3. **记录回归结果**
   ```
   回归测试 - {版本}
   - 回归用例数：{数量}
   - 通过：{数量}
   - 失败：{数量}
   - 结论：{是否通过}
   ```

### 步骤7：测试报告编写

**目的**：记录测试执行结果。

**操作**：

1. **汇总测试数据**
   - 用例执行数量
   - 通过率
   - 缺陷数量
   - 严重程度分布

2. **编写测试结论**
   - 测试是否通过
   - 是否可以上线
   - 遗留问题说明

3. **输出测试报告**
   - 保存至 `docs/testreport/{模块}/`
   - 更新SUMMARY.md

### 步骤8：创建GitHub Project工作项

**目的**：按照团队协作规范，更新任务状态。

**操作**：

```bash
# 更新测试任务状态
gh issue edit <issue-number> --body "## 测试状态\nDone

## 测试结果
- 总用例数：{数量}
- 通过：{数量}
- 失败：{数量}

## 缺陷列表
- BUG_XXX: {描述} - {状态}

## 测试结论
{通过/不通过}"

# 关闭测试任务
gh issue close <issue-number>
```

## 五、测试执行原则

### 5.1 测试优先级

| 优先级 | 覆盖要求 | 执行时机 |
|--------|----------|----------|
| P0 | 100%执行，100%通过 | 每次测试必执行 |
| P1 | 90%以上执行，90%以上通过 | 正常测试执行 |
| P2 | 80%以上执行，80%以上通过 | 时间允许时执行 |

### 5.2 测试通过标准

| 测试类型 | 通过标准 |
|----------|----------|
| P0用例 | 100%通过 |
| P1用例 | ≥90%通过 |
| P2用例 | ≥80%通过 |
| 缺陷修复 | 相关用例100%通过 |

### 5.3 测试环境要求

| 环境 | 用途 | 数据要求 |
|------|------|----------|
| 开发环境 | 日常测试 | 可反复修改 |
| 测试环境 | 集成测试 | 独立数据 |
| 预生产环境 | UAT/验收 | 生产级数据 |

### 5.4 缺陷关闭标准

- 相关测试用例100%通过
- 缺陷修复已验证
- 无遗留问题
- 代码已合并

## 附录E：测试执行脚本

### 测试自动化运行器

**脚本位置**: `.agents/skills/opentms-test-execution/scripts/run_tests.py`

**功能**:
- 列出可用测试套件
- 运行指定测试套件

- 生成测试报告
- 停止运行中的测试

```bash
# 列出可用测试套件
python .agents/skills/opentms-test-execution/scripts/run_tests.py list

# 运行基于数据模块测试
python .agents/skills/opentms-test-execution/scripts/run_tests.py run basedata

python .agents/skills/opentms-test-execution/scripts/run_tests.py run ac

python .agents/skills/opentms-test-execution/scripts/run_tests.py run at

python .agents/skills/opentms-test-execution/scripts/run_tests.py run all

# 停止运行中的测试
python .agents/skills/opentms-test-execution/scripts/run_tests.py stop

# 查看测试报告
python .agents/skills/opentms-test-execution/scripts/run_tests.py report basedata
```
