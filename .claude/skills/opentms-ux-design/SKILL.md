# Open-TMS UX交互设计 Skill (UX)

## 简介

本skill用于Open-TMS项目的UX交互设计，指导UX设计师完成从需求到界面原型的完整流程。

---

## 一、触发条件

当需要进行以下工作时触发：PM分配界面设计任务、PRD中标注"UX待设计"的功能、已有界面需要优化重构、用户提出界面改进需求。

触发信号：PM发送含PRD链接的设计任务、PRD标注"UX待设计"、PM-Lead分配界面优化任务。

---

## 二、输入要求

### 2.1 必须输入

- **PRD文档**: PM提供 — 功能需求文档
- **设计系统规范**: `docs/原型/Open-TMS界面原型与设计规范.md` — 配色、字体、间距等规范
- **模块已有原型**: `docs/原型/M{x}-{模块名}UX原型.md` — 同模块已有原型参考
- **模块历史摘要**: `docs/原型/{模块}/SUMMARY.md` — 本模块历史设计记录（若存在）

### 2.2 可选输入

- **竞品调研资料**: FIS Quantum/SAP界面参考
- **用户研究资料**: PM-Lead提供的用户访谈、调研报告
- **可用性测试报告**: QA提供的已有界面可用性问题

---

## 三、输出规范

### 3.1 交付件输出标准

> 📦 **PM-Lead v2026-07-10 决定**:UX 类产物统一以 **HTML** 格式输出(.md 不再作为主交付物,仅做归档索引)。HTML 模板可双击在浏览器打开,内置 Element Plus + Vue 3 CDN,直接呈现交互与样式。

每个原型文档必须包含: 模块导航结构、页面清单（含路径）、页面原型详述（交互规范 + 字段规范 + 业务流程）、组件状态说明。

**模板**:`references/prototype-template.html` — 直接复制该文件,按变量替换生成。

**存放路径**:`docs/原型/M{x}-{模块名}UX原型.html`(M3 之前的旧 .md 文件保留作为归档,可继续引用)。

### 3.2 设计标注规范

每个界面原型需包含: 元素尺寸标注、间距规范说明、交互行为描述、状态变化说明。

### 3.3 存放路径规范

```
docs/原型/
├── Open-TMS界面原型与设计规范.md  # 全局设计系统
├── common/docs/                    # 公共组件原型
├── M1-基础数据/docs/              # M1模块原型 + SUMMARY.md
├── M2-资金运营/docs/              # M2模块原型
├── M3-金融工具/docs/              # M3模块原型
├── M4-风险管理/docs/              # M4模块原型
└── M5-分析报表/docs/              # M5模块原型
```

> 所有新增原型文件后缀为 `.html`;`SUMMARY.md` 例外(仍是 markdown 索引)。

### 3.4 设计摘要标准

每次完成一组界面设计后，更新 `docs/原型/{模块}/SUMMARY.md`，记录: 完成的页面、遇到的问题及解决方案、设计决策、待确认事项。

## 四、执行步骤

### 步骤1：业界洞察

读取 `open-tms功能特性清单.md`，研究FIS Quantum、SAP、Murex等业界产品的界面设计（布局、交互模式、信息密度、数据可视化）。

对标模板见 `references/industry-benchmarks.md`（product-design skill）。

### 步骤2：读取历史摘要

检查 `docs/原型/{模块}/SUMMARY.md`，了解已完成页面、设计决策、待优化界面。若为新模块则创建新摘要文件。

### 步骤3：读取PRD理解需求

详细阅读PRD，识别关键用户角色和使用场景，标注需要设计的页面清单。

### 步骤4：界面原型设计

1. 根据PRD功能清单设计页面结构
2. 遵循设计系统规范（配色、字体、间距、组件规格）
3. 设计交互流程（列表页操作、表单录入、状态变化和反馈）
4. 输出界面原型文档，文件命名格式: `M{x}-{模块名}UX原型.html`(2026-07-10 起统一 HTML)

设计系统速查见 `references/design-system-cheatsheet.md`。

### 步骤5：检查设计规范一致性

对照 `docs/原型/Open-TMS界面原型与设计规范.md` 检查配色、字体字号、间距（8px网格）、按钮样式、表格规格、表单布局、交互动画。

检查结果处理: 符合规范则继续；不符合则修改设计或询问用户是否修改规范。

### 步骤6：与PM确认设计

向PM演示设计稿，确认功能覆盖完整、交互流程顺畅、状态反馈清晰。

### 步骤7：创建GitHub Project工作项

创建前端开发Task和US。具体命令 > 详见 `opentms-pm-lead` 第九节。

### 步骤8：生成设计摘要

更新 `docs/原型/{模块}/SUMMARY.md`。

## 五、业界优秀实践参考

企业级TMS界面设计原则:

1. **数据密度与可读性平衡**: 通过分组、折叠组织信息，关键数据突出
2. **操作效率优先**: 键盘快捷键、批量操作、默认值和常用选项置顶
3. **状态反馈清晰**: 加载中/成功/失败状态分明，错误信息有操作指引
4. **一致性原则**: 同类功能保持一致交互模式、视觉风格、术语表述
5. **容错设计**: 操作前确认、支持撤销、防止误操作

> 详细对标分析和组件设计模式见 `references/ux-patterns.md`。

## 七、质量标准

### 7.1 设计质量检查点

| 检查项 | 标准 | 权重 |
|--------|------|------|
| 功能覆盖完整性 | 覆盖PRD需求的100% | 25% |
| 交互流程正确性 | 符合业务逻辑 | 20% |
| 设计规范一致性 | 符合设计系统 | 20% |
| 可用性 | 符合易用性原则 | 15% |
| 无障碍性 | 符合WCAG标准 | 10% |
| 响应式适配 | 符合断点规范 | 10% |

### 7.2 量化指标

| 指标 | 目标值 | 最低值 |
|------|--------|--------|
| 规范符合率 | 100% | 95% |
| 交互状态覆盖率 | 100% | 90% |
| 组件复用率 | >=70% | 50% |
| 设计稿交付及时率 | 100% | 90% |

### 7.3 评审通过标准

- [ ] 所有PRD中的界面需求已设计
- [ ] 交互流程符合业务逻辑
- [ ] 符合设计系统规范
- [ ] PM确认通过
- [ ] 已创建前端开发任务
