## 一、模块概述

**模块名称**: cashflow - 实际现金流管理
**功能定位**: 管理银行账户的实际现金流(Actual Cashflow)，用于资金头寸监控、对账和流动性管理
**用户角色**: 资金管理人员、财务人员、资金经理

**与AT交易关系**:
- AT交易执行后自动生成对应的AC现金流记录
- AC是AT交易的影子，记录资金实际流动

---

## 二、交易类型定义

| 类型 | 说明 | 来源 | 优先级 |
|------|------|------|--------|
| Bank Account Transfer | 由账户转账生成的现金流 | AT交易执行 | P0 |
| Statement Line | 由银行对账单生成的现金流 | 银行对账导入 | P0 |
| Sweep Transaction | 由资金归集生成的现金流 | 现金池归集 | P1 |
| Cash Leveling | 由资金平划生成的现金流 | 手动/自动调拨 | P1 |

### 3.3 现金流状态机

```
┌──────────┐     clear      ┌─────────┐    reconcile    ┌────────────┐
│  Created │ ──────────────→│ Cleared │ ───────────────→│ Reconciled │
└──────────┘                └─────────┘                  └────────────┘
      │                          │
      │ cancel                   │ cancel
      ↓                          ↓
┌──────────┐                ┌──────────┐
│ Canceled │                │ Canceled │
└──────────┘                └──────────┘
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| Created | 已创建，待清分 | clear, cancel |
| Cleared | 已清分，待对账 | reconcile, cancel |
| Reconciled | 已对账(终态) | - |
| Canceled | 已取消 | - |

**状态流转规则**:
1. Created → Cleared: 执行清分操作(clear)
2. Cleared → Reconciled: 执行对账操作(reconcile)
3. Created/Cleared → Canceled: 执行取消操作(cancel)
4. Reconciled为终态，不可逆，不可取消

## 五、业务规则

### 5.1 编号规则
- **格式**: `CF` + 银行账户编号(4位) + `yyyyMMdd` + 序号(4位)
- **示例**: `CFBJ202606010001`
- **序号**: 每日独立计数，从0001开始

### 5.2 金额规则
- **精度**: DECIMAL(38,18) - 38位总长，18位小数
- **校验**: 金额必须大于0
- **舍入**: 按币种精度要求舍入

### 5.3 日期规则
- **现金流日期**: 不能晚于当前系统日期
- **起息日**: 可晚于现金流日期(预付交易)
- **工作日校验**: 起息日需为工作日(非节假日)

### 5.4 清分规则
- **自动清分条件**: 金额完全匹配，方向相反，日期相近
- **手工清分**: 可跨账户清分(同一业务单元内)
- **清分记录**: 记录清分时间、操作人、匹配依据

### 5.5 对账规则
- **自动对账**: 基于来源编号(Source Ref)精确匹配
- **差异记录**: 不匹配记录记为差异，允许手工处理
- **差异处理方式**: 确认银行差错 / 确认企业差错 / 挂账处理

### 5.6 权限规则
- 用户只能看到有权限的业务单元/银行账户的现金流
- 清分/对账操作需有对应权限

| 汇总报表 | 按各维度汇总数据正确 |
