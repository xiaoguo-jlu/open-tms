# AC/AT Transaction Financial Instruments Implementation Plan

**Date**: 2026-05-31
**Updated**: 2026-05-31 (requirements updated)
**Objective**: Implement AC (Actual Cashflow) and AT (Account Transfer) transaction financial instruments, aligned with FIS Quantum treasury management standards

---

## Context

The Open-TMS project is in M1 (Foundation Data Module) and needs to develop AC/AT transaction capabilities. AC represents actual cashflows from bank operations, while AT represents account transfers between enterprise bank accounts. FIS Quantum's architecture emphasizes:
- Transaction-Centric Data Model with configurable workflows
- Bank-Agnostic Design for multi-bank integrations
- Multi-Level Limit System with approval workflows

**Key Requirements (Updated 2026-05-31)**:
1. **Approval naming**: Use `approve` instead of `authorize` - workflow: submit → approve (N layers)
2. **ApprovalRule integration**: Determine if approval needed + approval layers via ApprovalRule service
3. **Amount precision**: `DECIMAL(38,18)` for all transaction amounts (38 total, 18 decimal)
4. **Instrument separation**: AC instruments and AT instruments use different pages/APIs
5. **UI reference**: Style reference FIS Quantum TMS - professional, financial-grade UI
6. **Transaction abstraction**: Abstract common transaction workflow for future deal types (FX, IRS, etc.)
7. **Accounting events**: On transaction creation, generate corresponding accounting events
8. **基础数据选择**: Use dialog/popup for selecting BusinessUnit, Counterparty, Instrument (参考FIS)

---
