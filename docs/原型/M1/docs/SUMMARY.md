## 设计过程记录

### 2026-06-21 - AC交易UX设计（基于 DealMap v2.0）
**完成内容**:
- M1-AC交易UX原型 - 5个核心页面
  - AC 交易列表页（高密度表格 + 多维筛选）
  - AC 创建/编辑抽屉（520px，底部展示系统自动生成内容）
  - AC 交易详情页（关键信息卡 + 4 个 Tab：基本信息/DealMap/现金流/操作历史）
  - AC 审批弹窗（基于 Action 列表，审批不改变 DealMap/Cashflow）
  - 删除确认弹窗（展示级联影响）

**核心设计理念落地**:
- ✅ 列表采用高密度表格，对标 FIS Quantum
- ✅ 创建抽屉底部展示"系统将自动生成 Action/DealMap/Cashflow"
- ✅ DealMap 时间线可视化展示 Action→DealMap 触发关系与软删历史
- ✅ 审批弹窗基于 Action 列表，强调"审批不影响 DealMap/Cashflow 状态"
- ✅ 删除二次确认展示级联软删范围

**遇到的问题**:
- v2.0 自动生成机制对用户感知弱 → 解决方案：保存成功 Toast + 抽屉底部展示生成内容
- DealMap 时间线需要区分"软删"与"活动"状态 → 解决方案：灰色 + 删除线 + ❌ 图标
- 审批不触达 DealMap/Cashflow 需要明确告知用户 → 解决方案：审批弹窗顶部提示

**设计决策**:
- 列表筛选维度：交易编号/方向/状态/主体/日期范围
- 状态标签：新建（蓝）/ 待审批（黄）/ 已审批（绿）/ 已删除（灰）
- DealMap 时间线采用左右树状结构展示
- 抽屉宽度 520px（与资金管理主体一致）
- 已删除行只显示详情按钮，禁止二次操作

**待确认事项**:
- [ ] AC 列表是否需要支持按 DealMap 状态筛选
- [ ] 审批弹窗是否需要支持批量审批多个 Action

### 2026-05-26 - 资金管理主体UX设计
**完成内容**:
- M1-资金管理主体UX原型 - 3个页面
  - 资金管理主体列表页（左右分栏布局）
  - 新增/编辑主体抽屉（折叠分组表单）
  - 主体详情页（Tab展示）

**遇到的问题**:
- 资金管理主体字段较多（基础+监管+会计+税务） → 采用折叠分组减少首屏信息密度
- 组织层级与列表联动 → 采用左侧组织树 + 右侧列表的经典设计

**设计决策**:
- 列表页采用左右分栏：左侧组织树筛选，右侧列表展示
- 表单采用折叠分组：基础信息默认展开，监管/会计税务默认折叠
- 详情页采用Tab分类：基本信息/监管信息/会计准则/税务配置/关联信息

**待确认事项**:
- [ ] 组织树的展示深度是否需要限制
- [ ] 关联信息Tab的展示内容是否完整
