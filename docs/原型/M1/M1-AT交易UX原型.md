## 四、核心交互流程（v2.0 设计理念）

### 4.1 AT 创建流程

```
列表页 → 点击 [+ 新建] → 抽屉滑出（空表单）
    ↓
填写字段（实时校验 + transfer_type 自动识别）
    ├─ 选择源账户（按业务主体过滤）
    ├─ 选择目标账户（联动识别 transfer_type）
    ├─ 录入 source_amount
    ├─ 若跨币种 → 录入 exchange_rate → 自动计算 dest_amount
    ↓
点击 [保存] → 后端事务
    ├─ INSERT Action(CREATE)
    ├─ INSERT Deal(status=New)
    ├─ INSERT AtDeal
    ├─ INSERT 4 DealMap（2 TRANSFER + 2 CASHFLOW，SOURCE+DESTINATION）
    ├─ INSERT 2 Cashflow（各关联一个 TRANSFER DealMap）
    └─ ❌ 不生成 DealImage
    ↓
抽屉关闭 + 列表刷新 + Toast 提示"保存成功"
   （提示展示 4 条 DealMap + 2 条 Cashflow 摘要）
```

### 4.2 AT 修改流程

```
列表页 → 点击 [✏️ 编辑] → 抽屉滑出（带回显）
    ↓
修改字段（账户/金额/汇率）→ 点击 [保存] → 后端事务
    ├─ INSERT Action(UPDATE) - 新独立 Action
    ├─ UPDATE Deal（字段值）
    ├─ UPDATE AtDeal
    ├─ UPDATE DealMap SET deleted='1'  ← 软删旧 4 条 DealMap
    ├─ INSERT 新 4 条 DealMap  ← 关联新 Action
    ├─ UPDATE Cashflow SET dealmap_number  ← 指向新 DealMap（2 条）
    └─ INSERT DealImage(v+1)  ← 记录修改前旧值
    ↓
抽屉关闭 + 列表刷新 + Toast 提示
```

### 4.3 AT 删除流程

```
列表页 → 点击 [🗑️ 删除] → 二次确认弹窗
    "确认删除 AT 交易 AT202606210001？此操作将级联软删
     关联的 4 条 DealMap 和 2 条 Cashflow，并记录操作历史。"
    ↓
点击 [确认删除] → 后端事务
    ├─ INSERT Action(DELETE)
    ├─ UPDATE Deal SET deleted='1'
    ├─ UPDATE AtDeal SET deleted='1'
    ├─ UPDATE DealMap SET deleted='1'  ← 4 条级联
    ├─ UPDATE Cashflow SET deleted='1'  ← 2 条级联
    └─ INSERT DealImage(v+1)
    ↓
列表刷新 + Toast 提示"已删除"
```

### 4.4 AT 审批流程（基于 Action）

```
详情页 → 点击 [审批] → 弹出 Action 列表模态框
    "选择需要审批的 Action（可多选）"
    ├─ □ ACT202606210001 | CREATE | Pending   | [查看详情]
    ├─ □ ACT202606210002 | UPDATE | Pending   | [查看详情]
    └─ □ ACT202606210003 | DELETE | Pending   | [查看详情]
    ↓
勾选 Action → 点击 [审批通过] 或 [驳回] → 填写审批意见
    ↓
后端：UPDATE Action SET approval_status1='Approved', approver1=...
    ↓
    ⚠️ DealMap / Cashflow 任何状态都不变！（含 4 条 DealMap 和 2 条 Cashflow）
    ↓
模态框关闭 + 详情页刷新 + Toast 提示
```

**宽度**: 580px（比 AC 宽 60px，容纳双账户并排布局）

**字段规范**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| 交易编号 | readonly | 系统 | 创建时自动生成（AT+yyyyMMdd+序号） |
| 业务主体 | select+弹框 | Y | 从基础数据-管理主体选择（仅启用） |
| 转账类型 | select | Y | 自动识别，可手工覆盖 |
| 付出账户 | select+弹框 | Y | 从基础数据-银行账户选择（按主体过滤） |
| 收入账户 | select+弹框 | Y | ≠ 付出账户；从基础数据-银行账户选择 |
| 付出金额 | input+money | Y | 数字，DECIMAL(38,18)，> 0 |
| 付出币种 | readonly | - | 跟随源账户币种 |
| 收入金额 | input+money | C | 跨币种自动计算；同币种可手工 |
| 收入币种 | readonly | - | 跟随目标账户币种 |
| 汇率 | input+number | C | 跨币种必填；同币种=1.0 自动 |
| 起息日 | datepicker | Y | 默认为今天 |
| 支付方式 | select | N | 转账/电汇/RTGS/内部 |
| 转账用途 | input+text | N | 最大 200 字符 |
| 备注 | textarea | N | 最大 500 字符 |

**联动规则**：

| 触发 | 联动效果 |
|------|---------|
| 选源账户 | 展示币种 + 业务主体；自动识别 transfer_type |
| 选目标账户 | 展示币种 + 业务主体；若与源账户业务主体不同 → transfer_type=CROSS_COMPANY |
| 选源/目标账户（含跨境） | 若 country 不同 → transfer_type=CROSS_BORDER |
| 录入 source_amount | 若同币种，dest_amount 自动 = source_amount |
| 录入 exchange_rate | dest_amount = source_amount × exchange_rate 实时计算 |
| 切换币种 | 自动重新计算 dest_amount（若有汇率） |

**联动规则**：

| 触发 | 计算 |
|------|------|
| 输入 source_amount + 已有 rate | dest_amount = source_amount × rate |
| 输入 source_amount + 已有 dest_amount | rate = dest_amount / source_amount |
| 切换源/目标账户币种 | 提示重新输入汇率（若已存在） |
| 同币种 | 汇率自动设为 1.0；dest_amount 自动 = source_amount |

## 七、关键 UX 设计决策

| # | 决策 | 原因 |
|---|------|------|
| 1 | 列表页采用双账户高密度表格 | AT 业务核心是双账户，必须并排展示 |
| 2 | 抽屉宽度 580px（比 AC 宽 60px） | 容纳双账户并排布局 + 跨币种联动 |
| 3 | 转账类型自动识别 + 可手工覆盖 | 减少用户输入，但保留灵活性 |
| 4 | 双账户间显示 🎯 动画箭头 | 强化"双腿转账"概念，与 AC 单边区分 |
| 5 | 跨币种时 dest_amount 实时联动 | 防止汇率填错导致金额不一致 |
| 6 | 详情页 DealMap 采用 2×2 矩阵 | 直观展示双腿对称（SOURCE/DESTINATION） |
| 7 | SOURCE 用蓝色，DESTINATION 用绿色 | 视觉区分双腿；与色板系统保持一致 |
| 8 | 保存成功提示展示 4 DealMap + 2 Cashflow 摘要 | 让用户感知 v2.0 双腿自动生成逻辑 |
| 9 | 审批弹窗明确写"4 DealMap / 2 Cashflow" | 强化双腿业务的影响力 |
| 10 | 删除二次确认明确"4 条 DealMap + 2 条 Cashflow" | 用户感知双腿级联影响 |
| 11 | transfer_type 三色徽章 | 视觉区分同公司/跨公司/跨境 |
| 12 | 联动计算字段用绿色背景 | 视觉提示"自动计算，不可手工" |

## 九、AT vs AC UX 关键差异对比

| 维度 | AC UX | AT UX | 说明 |
