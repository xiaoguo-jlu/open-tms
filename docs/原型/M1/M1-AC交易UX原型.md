## 四、核心交互流程（v2.0 设计理念）

### 4.1 AC 创建流程

```
列表页 → 点击 [+ 新建] → 抽屉滑出（空表单）
    ↓
填写字段（实时校验）
    ↓
点击 [保存] → 后端事务
    ├─ INSERT Action(CREATE)
    ├─ INSERT Deal(status=New)
    ├─ INSERT AcDeal
    ├─ INSERT DealMap(ActualCashflow)  ← 自动生成
    ├─ INSERT Cashflow(dealmap_number) ← 自动生成
    └─ ❌ 不生成 DealImage
    ↓
抽屉关闭 + 列表刷新 + Toast 提示"保存成功"
```

### 4.2 AC 修改流程

```
列表页 → 点击 [✏️ 编辑] → 抽屉滑出（带回显）
    ↓
修改字段 → 点击 [保存] → 后端事务
    ├─ INSERT Action(UPDATE) - 新独立 Action
    ├─ UPDATE Deal（字段值）
    ├─ UPDATE AcDeal
    ├─ UPDATE DealMap SET deleted='1'  ← 软删旧 DealMap
    ├─ INSERT 新 DealMap(ActualCashflow)  ← 关联新 Action
    ├─ UPDATE Cashflow SET dealmap_number  ← 指向新 DealMap
    └─ INSERT DealImage(v+1)  ← 记录修改前旧值
    ↓
抽屉关闭 + 列表刷新 + Toast 提示
```

### 4.3 AC 删除流程

```
列表页 → 点击 [🗑️ 删除] → 二次确认弹窗
    "确认删除 AC 交易 AC202606210001？此操作将级联软删
     关联的 DealMap 和 Cashflow，并记录操作历史。"
    ↓
点击 [确认删除] → 后端事务
    ├─ INSERT Action(DELETE)
    ├─ UPDATE Deal SET deleted='1'
    ├─ UPDATE AcDeal SET deleted='1'
    ├─ UPDATE DealMap SET deleted='1'   ← 级联
    ├─ UPDATE Cashflow SET deleted='1'  ← 级联
    └─ INSERT DealImage(v+1)
    ↓
列表刷新 + Toast 提示"已删除"
```

### 4.4 AC 审批流程（基于 Action）

```
详情页 → 点击 [审批] → 弹出 Action 列表模态框
    "选择需要审批的 Action（可多选）"
    ├─ □ ACT202606210001 | CREATE | Pending   | [查看详情]
    ├─ □ ACT202606210002 | UPDATE | Pending   | [查看详情]
    └─ □ ACT202606210003 | DELETE | Pending   | [查看详情]
    ↓
勾选 Action → 点击 [审批通过] 或 [驳回] → 填写审批意见
    ↓
后端：UPDATE Action SET approval_status1='Approved', approver1=...
    ↓
    ⚠️ DealMap / Cashflow 任何状态都不变！
    ↓
模态框关闭 + 详情页刷新 + Toast 提示
```

| 弹出框选择 | 业务主体/对手方等基础数据均通过弹框选择（仅启用数据） |
| 自动联动 | 选择主体后，自动过滤该主体的银行账户 |

**交互规范：**

| 元素 | 规范 |
|------|------|
| Action 列表 | 按时间倒序展示该 Deal 的所有 Pending Action |
| 多选 | 支持勾选多个 Action 批量审批 |
| 查看详情 | 展开显示 Action 的变更明细（前后对比） |
| 审批通过 | UPDATE Action SET approval_status1='Approved', approver1=当前用户 |
| 驳回 | UPDATE Action SET approval_status1='Rejected' + 必填审批意见 |
| 取消 | 关闭弹窗，不做任何修改 |
| 审批意见 | 必填（驳回时强制） |

**审批后效果（关键）：**

```
✅ 审批通过
   • Action 状态变更：Pending → Approved
   • DealMap 状态：不变（始终 Active）
   • Cashflow 状态：不变（始终 Created）
   • Deal 状态：当所有 Action 都 Approved 时 → Approved

❌ 驳回
   • Action 状态变更：Pending → Rejected
   • DealMap / Cashflow 状态：均不变
```

## 七、关键 UX 设计决策

| # | 决策 | 原因 |
|---|------|------|
| 1 | 列表页采用高密度表格 | 对标 FIS Quantum，企业级用户需高效浏览大量数据 |
| 2 | 创建/编辑使用抽屉（520px） | 用户操作频繁，避免页面跳转 |
| 3 | 保存成功提示展示生成的 DealMap/Cashflow 摘要 | 让用户感知 v2.0 自动生成逻辑 |
| 4 | DealMap 时间线用图状可视化 | 直观展示 Action→DealMap 触发关系与软删历史 |
| 5 | 审批弹窗基于 Action 列表 | 符合 v2.0 审批设计（不触达 DealMap/Cashflow） |
| 6 | 删除二次确认展示级联影响 | 用户感知软删范围，避免误操作 |
| 7 | 已删除行只显示详情按钮 | 不允许二次删除/编辑 |
| 8 | 抽屉底部展示系统将自动生成的字段 | 提前告知用户 v2.0 自动生成机制 |
