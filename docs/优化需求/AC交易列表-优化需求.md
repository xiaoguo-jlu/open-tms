# AC 交易列表 优化需求

**创建日期**: 2026-07-07
**优先级**: P1
**状态**: 待评审
**所属模块**: dealing
**关联页面**: /dealing/ac-deal

---

## 需求总览

AC 交易(账户间转账 / Account-to-Account)列表页存在 **3 项 P1 体验问题**,主要集中在筛选区字段不足、表格列被裁切以及操作列缺失等方面。该页面是 Dealing 模块的入口页面之一,直接关系到交易员日常查找与处理交易的效率,需优先优化。

## P1 - 必须优化

### AC-1: 筛选字段不全

**问题描述**
当前列表页筛选区仅暴露 4 个字段(交易编号、对手方、交易类型、状态),无法覆盖交易员日常检索场景。比对国际同类系统(FIS Quantum、Murex)的同类页面,筛选区通常应提供 8-10 个字段,以支持多维度组合查询。

**当前截图位置**: /tmp/ac-deal-list-before.png
**用户影响**
- 交易员无法按"工具/支付方式/起息日范围"精确定位交易
- 风控/审批人无法按"交易员/对手方/审批人"过滤待办
- 历史数据复盘困难,缺少按"创建时间/起息日"的时间窗口检索

**验收标准**
1. 筛选区至少支持 8 个字段:交易编号、对手方、工具、交易类型、交易员、起息日范围、支付方式、状态、创建时间范围
2. 每个筛选字段支持单独清空与组合查询
3. 查询响应时间 < 500ms(分页 + 筛选)
4. 筛选条件持久化到 URL query,刷新页面后仍保留

**预估工作量**: M

---

### AC-2: 表格列字段不全,表头列被裁切

**问题描述**
当前 el-table 列字段过少,缺少以下关键信息列:
- 状态(只有"最新 Action",无交易自身状态)
- 操作列(查看 / 编辑 / 复制 / 删除 / 审批)
- 起息日(Value Date)
- 名义本金(Notional)
- 交易员(Trader)

同时,在 1440px 屏幕宽度下,右侧"最新 Action"和"操作"列被裁切,需要横向滚动才能看到,严重影响操作效率。

**当前截图位置**: /tmp/ac-deal-list-before.png
**用户影响**
- 关键决策信息(状态、起息日、名义本金)不在视野内,需进入详情才能看到
- 操作列被裁切意味着用户无法直接对单条交易做"审批/编辑/删除"等动作
- 横向滚动条打断视觉流,降低扫描效率

**验收标准**
1. 表格至少包含以下列:交易编号、对手方、工具、交易类型、起息日、名义本金、交易员、状态、最新 Action、操作
2. 在 1280px 及以上分辨率下,操作列必须可见,无需横向滚动
3. 金额列右对齐,千分位分隔
4. 状态列使用 Tag 组件,颜色语义化(草稿/待审批/已审批/已驳回/已完成)

**预估工作量**: M

---

### AC-3: 操作列未固定,被裁切

**问题描述**
表格的"操作"列未设置 `fixed="right"`,在列较多或屏幕较窄时被自动挤出可视区域,导致用户看不到"查看/编辑/审批"等关键操作按钮。这是同类金融系统的常见反模式。

**当前截图位置**: /tmp/ac-deal-list-before.png
**用户影响**
- 用户不知道列表上是否可对单条交易做进一步操作
- 即便知道,也需要滚动到右侧才能点,鼠标轨迹成本高

**验收标准**
1. 操作列固定在表格右侧,设置 `fixed="right"`,宽度 160-200px
2. 操作按钮使用图标 + 文字双形态,鼠标悬浮 Tooltip 提示完整动作名
3. 根据状态动态显示可执行操作(如"已审批"状态下不显示"审批"按钮)
4. 至少包含:查看详情、编辑(草稿态)、复制、审批(待审批态)、删除(草稿态)

**预估工作量**: S
