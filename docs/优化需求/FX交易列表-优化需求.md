# FX 交易列表 优化需求

**创建日期**: 2026-07-07
**优先级**: P1
**状态**: 待评审
**所属模块**: dealing / fx
**关联页面**: /dealing/fx-deal

---

## 需求总览

FX 交易(外汇交易 / Foreign Exchange)列表页存在 **3 项 P1 体验问题**,其中 **FX-1 为高优先级 UX 反模式**:筛选区的"管理主体/对手方"用了 `<el-input type="number">` 让用户输入 ID,这在金融系统里属于典型反模式,ID 对用户无意义,必须改为下拉选择并显示名称。FX-2、FX-3 属于通用表格列不足与操作列裁切问题。

## P1 - 必须优化

### FX-1 ⭐: ID 输入框应改为下拉选择

**问题描述**  **(优先级最高)**
当前 FX 列表的"管理主体 ID"和"对手方 ID"筛选字段使用了 `<el-input type="number">`(数字调节器,带 +/- 按钮),这在金融领域是典型反模式:
1. 用户记不住"管理主体"或"对手方"的数字 ID,只能模糊搜索
2. 数字调节器让用户点 +/- 加减数字,毫无业务含义
3. 即便输入正确 ID,也无法确认是否选对(没有名称回显)
4. 大型财资系统(FIS / Murex / Kyriba)中,所有业务对象筛选都使用下拉选择 + 名称展示 + 模糊搜索

**当前截图位置**: /tmp/fx-deal-list-before.png
**用户影响**
- 交易员实际使用时只能放弃该筛选条件,改用交易编号精确查找
- 风控按对手方筛选交易时,因为不知道对手方 ID,无法使用
- 录入员新建交易后想回查,因不知道系统分配的 ID,无法定位

**验收标准**
1. "管理主体"字段改为 `<el-select>`,数据来源为 Subsidiary 服务 `/api/v1/basedata/subsidiary/list`,显示字段为 `{subsidiaryNo} - {subsidiaryName}`,value 绑定 `id`
2. "对手方"字段改为 `<el-select>`,数据来源为 Counterparty 服务(若 dealing 模块有对应 API),显示字段为 `{counterpartyNo} - {counterpartyName}`,value 绑定 `id`
3. 两个 `<el-select>` 均启用 `filterable` 与 `remote-search`,支持按名称/编号模糊搜索
4. 选中后显示名称(而非 ID),列表查询时按 ID 传参
5. 提供"清空"按钮,允许快速重置
6. 当下拉数据为空时,显示空状态提示"暂无管理主体/对手方数据,请先在基础数据中维护"
7. 加载下拉数据时显示 loading 状态

**预估工作量**: M

### FX-2: 表格列字段缺失

**问题描述**
当前表格缺少 FX 业务的核心字段:
- 起息日(Value Date)
- 到期日(Maturity Date,远期/掉期时必填)
- 名义本金(Notional Amount)
- 状态(Status)
- 汇率(Spot Rate / Forward Rate)
- 期限(Tenor,如 1M / 3M)

**当前截图位置**: /tmp/fx-deal-list-before.png
**用户影响**
- 风控/资金计划岗无法在列表上扫描"未来 7 天到期"的外汇交易
- 名义本金缺失导致无法快速评估单笔交易对敞口的影响
- 状态缺失让用户分不清"已审批/未审批/已成交/已取消"

**验收标准**
1. 表格至少包含以下列:交易编号、买卖方向、货币对、名义本金、汇率、起息日、到期日、期限、状态、管理主体、对手方、交易员、操作
2. 买卖方向用 Tag 区分(买入蓝色 / 卖出橙色)
3. 名义本金 / 汇率右对齐,千分位分隔,汇率保留 4-6 位小数
4. 起息日 / 到期日支持按日期排序
5. 货币对使用标准 ISO 代码(如 USD/CNY)
6. 在 1440px 分辨率下所有列可见(或操作列固定右侧后其余列横向滚动)

**预估工作量**: M

---

### FX-3: 表头列被裁切,"操作"列不可见

**问题描述**
操作列未设置 `fixed="right"`,列被自动裁切。同时表头列字段名也被截断显示。

**当前截图位置**: /tmp/fx-deal-list-before.png
**用户影响**
- 用户无法在列表页直接对 FX 交易执行"审批/对冲/平仓"等操作
- 削弱列表页的"操作中心"定位,沦为纯查询页

**验收标准**
1. 操作列固定右侧,设置 `fixed="right"`,宽度 180-220px
2. 至少包含:查看详情、编辑(草稿态)、审批(待审批态)、复制、对冲(已审批)、平仓(已成交)、删除(草稿态)
3. 表头各列宽合理,字段名不被截断
4. 操作按钮根据状态动态显隐

**预估工作量**: S
