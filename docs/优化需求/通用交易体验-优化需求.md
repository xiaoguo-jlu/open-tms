# 通用交易体验 优化需求

**创建日期**: 2026-07-07
**优先级**: P2
**状态**: 待评审
**所属模块**: 全局(基于 dealing 模块)
**关联页面**: /dealing/ac-deal、/dealing/at-deal、/dealing/fx-deal 及其余交易列表

---

## 需求总览

本文件登记 **10 项 P2 跨页面体验优化**,适用于 Open-TMS 所有交易类列表页(AC/AT/FX/IRS 等)以及全局框架层。这些问题单独看非阻塞,但累积起来严重影响系统的"专业感"与"操作效率",是同业最佳实践(FIS Quantum、Murex、SAP TRM、Kyriba)的基本配置。优化完成后整体体验将提升一个档次。

## P2 - 体验优化

### P2-1: 顶部 Header 太简陋

**问题描述**
当前 header 仅显示 logo + 面包屑,缺失企业级系统的标配模块:
- 全局搜索(按交易编号/对手方/账户)
- 用户菜单(头像、个人信息、修改密码、退出登录)
- 通知中心(待办、审批提醒、系统消息)
- 帮助/反馈入口(用户手册、问题反馈)
- 主题切换(可选)

**用户影响**
- 用户需逐页查找交易,无全局快速入口
- 系统消息触达不到用户,易遗漏审批待办
- 专业感缺失,与"企业级财资系统"定位不匹配

**验收标准**
1. Header 右侧包含:全局搜索框 + 通知中心(带未读小红点) + 用户菜单(头像下拉) + 帮助入口
2. 全局搜索支持跨交易类型(AC/AT/FX/IRS)模糊查询,回车跳转结果列表
3. 通知中心点击展开抽屉,展示最近 10 条待办/消息
4. 用户菜单包含:个人信息、修改密码、退出登录
5. Header 高度统一(建议 56px),与面包屑样式协调

**预估工作量**: L

---

### P2-2: 空数据状态太简单

**问题描述**
列表无数据时仅显示 Element Plus 默认的 "No Data" 文字,缺少插画、引导文案与主行动按钮,对新用户不友好。

**用户影响**
- 新用户看到"No Data"无法判断"是没数据?还是筛选错了?还是权限不够?"
- 没有"立即新建"按钮,需要去顶部找

**验收标准**
1. 自定义空状态组件 `<empty-state>`,包含:
   - 业务相关插画(SVG,空文件夹/空盒子/搜索无结果 三种状态)
   - 主标题(如"暂无交易记录")
   - 副标题(如"点击下方按钮创建第一笔交易,或调整筛选条件")
   - 主行动按钮"立即新建"(跳转新建页)
   - 次行动按钮"清除筛选"(清空所有筛选条件)
2. 三种状态自动适配:无筛选无数据 / 有筛选无数据 / 搜索无结果
3. 插画尺寸约 200x200px,居中显示

**预估工作量**: M

---

### P2-3: 顶部统计卡缺失

**问题描述**
业务列表页缺少顶部统计卡,无法一眼看到当日/当月的关键业务指标。在交易类系统里,统计卡是"驾驶舱"的标配。

**用户影响**
- 管理层无法快速掌握当日交易概况
- 交易员无法看到自己今日成交笔数
- 风控无法直观看到净敞口与待审批数

**验收标准**
1. 列表页顶部统一加入 4-6 个统计卡:
   - 今日成交笔数
   - 名义本金合计
   - 净敞口(按交易类型)
   - 待审批数
   - 锁汇额度占用(仅 FX)
   - 今日到期笔数(可选)
2. 统计卡点击可下钻到对应筛选后的列表
3. 数据每 60s 自动刷新(或手动刷新按钮)
4. 加载时显示骨架屏

**预估工作量**: L

---

### P2-4: 表格无排序提示

**问题描述**
表头没有 ↑↓ 排序图标,用户无法判断哪些列可排序。

**用户影响**
- 用户尝试点击列排序但无反应,体验困惑
- 即便可排序,也无法从视觉上识别可排序列

**验收标准**
1. 所有可排序列的表头显示排序图标(默认 ↑↓ 灰色,激活后 ↑ 或 ↓ 高亮)
2. 不可排序列不显示排序图标
3. 当前排序列高亮显示
4. 支持单列排序与多列排序(配置项)

**预估工作量**: S

---

### P2-5: 批量操作缺失

**问题描述**
列表仅"新建"按钮,无法批量审批、批量导出、批量删除。金融场景下,风控/财务经常需要批量处理同类型交易。

**用户影响**
- 审批 50 笔同类型交易需要逐个点击,效率极低
- 月末对账需要批量导出,目前只能逐条导出或导出全量

**验收标准**
1. 列表上方 toolbar 增加"批量操作"区域,根据勾选项数量动态启用
2. 至少支持:
   - 批量审批(待审批 → 已审批,需二次确认)
   - 批量导出(Excel/CSV,导出当前筛选后的全量数据,而非仅勾选项)
   - 批量删除(仅草稿态)
3. 批量操作前显示二次确认弹窗,告知"将对 X 条交易执行 XX 操作"
4. 操作完成后显示 Toast 反馈(成功 X 条,失败 Y 条)

**预估工作量**: L

---

### P2-6: 筛选区可折叠

**问题描述**
筛选区默认展开,占据约 1/4 屏幕高度,挤压数据表格。在用户已经设置好筛选条件后,通常希望折叠筛选区以获得更大数据展示空间。

**用户影响**
- 数据行可见数量少,需频繁翻页
- 在笔记本屏幕上尤其明显,体验差

**验收标准**
1. 筛选区右上角增加"折叠 / 展开"按钮(箭头图标)
2. 默认展开,折叠后仅保留一行筛选摘要(如"已筛选:对手方=XX, 状态=XX")
3. 折叠状态持久化到 localStorage,刷新后保持
4. 折叠 / 展开有平滑动画(200-300ms)

**预估工作量**: S

---

### P2-7: 页面加载状态缺失

**问题描述**
数据请求中无 loading 状态(无 spinner、骨架屏或遮罩),用户不知道系统在加载,容易以为页面卡死。

**用户影响**
- 在数据量大或网络慢时,用户多次点击按钮,引发重复请求
- 无视觉反馈,体验差

**验收标准**
1. 列表数据请求时显示骨架屏(行级骨架)或表格 loading 遮罩
2. 按钮点击后立即显示 loading 状态(如"审批中...")
3. 全屏 loading 仅用于首屏,二次筛选/分页用局部 loading
4. 加载超过 1s 时显示"加载中, 请稍候"提示文字
5. 慢请求(>1s)需要打日志埋点

**预估工作量**: S

---

### P2-8: 面包屑导航缺失

**问题描述**
页面顶部只有 header,无面包屑导航。侧边栏菜单虽然能反映层级,但侧边栏被折叠后用户容易迷路。

**用户影响**
- 用户从详情页返回列表时,不知道当前在哪个模块
- 深层页面(如"FX / 远期 / 3M / USD-CNY")无法快速回到上一层
- 不符合 Web 可访问性(WCAG)要求

**验收标准**
1. Header 下方增加面包屑组件,显示完整层级路径(如"首页 > 交易管理 > FX 交易 > 详情")
2. 每级面包屑可点击跳转
3. 当前页面包屑不可点击(灰色)
4. 移动端/窄屏可折叠中间层级

**预估工作量**: S

---

### P2-9: 分页器排版可紧凑

**问题描述**
Element Plus 默认分页器 `Total 0 | 10/page | < 1 > | Go to 1` 排版松散,占据空间大,信息密度低。

**用户影响**
- 分页器占用过多横向空间,挤压表格
- "Go to 1"输入框多余,点击页码即可

**验收标准**
1. 分页器精简为:`共 100 条 | 10条/页 | < 1 2 3 ... 10 >`,去掉"Go to"输入框
2. 提供"每页条数"下拉(20/50/100/200)
3. 总条数加载完成后以动画更新,避免闪烁
4. 分页器右侧可加入"跳转新建"快捷按钮

**预估工作量**: S

---

### P2-10: 筛选器日期组件优化

**问题描述**
当前日期筛选使用普通日期选择器,需要手动选择起止日期,操作繁琐。金融场景下"今日/本周/本月/本季度/本年"是高频时间窗口。

**用户影响**
- 选择"本月"需要点 2 次日历(起始 + 结束),操作成本高
- 不同用户对"本周"的定义不一致(周一/周日),系统应统一

**验收标准**
1. 日期筛选组件支持快捷标签:今日、昨日、本周、上周、本月、上月、本季度、上季度、本年、上年
2. 点击快捷标签自动填充日期范围
3. 仍保留手动选择日历的能力
4. "本周"统一为周一到周日(可配置)
5. 选中快捷标签时高亮显示

**预估工作量**: S
